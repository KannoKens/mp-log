# MPログ

その日に使える気力を **MP（残量）** として毎日記録し、無理をしそうな日を早めに知らせてくれる
セルフトラッキング Web アプリです。記録がたまると、睡眠や活動と MP の関係をふりかえれます。

ローカルで動く個人用アプリで、データは手元の SQLite に保存され、外部には送信されません。

## なぜ作ったか

体調や気力には波があるのに、手元に残るのは「今日はしんどかった」といった**文章での記録だけ**で、
毎日の数値データがありませんでした。それでは「何が自分を削っているのか」「どんな日の翌日に崩れるのか」が
推測にしかなりません。

そこで次の方針で作りました。

- **入力は数秒で終わるくらい軽くする**。続かなければ何も分からないため
- **ためてから傾向を見る**。数日分のデータで断定しない
- **崩れそうな兆候は記録した時点で知らせる**

## 主な機能

| 機能 | 画面 | 概要 |
| --- | --- | --- |
| 日次の記録 | `/` | MP・寝起き・活動タグ・メモを1日1件で記録。過去の日の記入・修正も可能 |
| 警告表示 | `/` | 没頭の連続や寝起きの悪さから、休息や減速をうながすメッセージを表示 |
| カレンダー | `/calendar` | MP を4色で塗り分けたヒートマップ。クラッシュした日には⚡を表示 |
| ふりかえり | `/insights` | 週ごとの推移と、寝起き・活動タグと MP の関係を集計 |
| JSON API | `/api/logs` | 全記録を JSON で取得 |
| 活動ごとの消費MP | （Python API） | 活動1件ごとに消費した MP を記録し、見積もりと実測のズレを集計 |
| リマインド通知 | — | その日が未記録のときだけ、朝と夜に Windows のトースト通知を表示（WSL 環境） |

### 日次の記録（`/`）

1日1件、次の項目を記録します。同じ日に保存し直すと上書きされます。
フォームの日付欄で過去の日を選ぶと、その日の記録を開いて記入・修正できます（URL では `/?d=YYYY-MM-DD`）。
未来の日付は選べません。

| 項目 | 入力方法 | 内容 |
| --- | --- | --- |
| MP | 4択 | その日の気力の残量（下表） |
| 寝起き | 3択 | 良い / 普通 / 悪い |
| 活動タグ | ボタン＋自由記述 | その日にやったこと・あったこと。カンマ（読点も可）区切りで複数入力 |
| メモ | 自由記述 | 一言メモ |

**MP の4段階**

| 段階 | 目安 | 代表値 |
| --- | --- | --- |
| 絶好調 | 余裕があり、重い作業もこなせる | 17 |
| 安全圏 | 普段どおり動ける | 10 |
| やや注意 | 無理をすると崩れそう | 7 |
| 危険 | 休むべき状態 | 3 |

代表値は、カレンダーの色分けやふりかえりの平均計算に使う数値です。

**活動タグ** のボタンは3段に分かれています。

| 段 | 中身 |
| --- | --- |
| よく使う | 直近90日で2回以上使ったタグ。一度自由記述したタグも、使い続ければここに出てくる |
| 登録済み | `config.py` の `ACTIVITY_TAGS` に登録したタグ |
| 体調・状態 | `没頭` 🌀 / `散歩` 🚶 / `苦しい夢` 😣 / `クラッシュ` ⚡ |

「体調・状態」のタグは警告やカレンダーの判定に使われます。
表記ゆれは自動で正規化されます（例: `悪夢` → `苦しい夢`、`さんぽ` → `散歩`、`没頭タスク` → `没頭`）。

入力画面には、直近14日分の記録も一覧で表示されます。

### 警告表示

トップページに、その日の状態に応じたメッセージを表示します。

| 条件 | 表示 |
| --- | --- |
| `没頭` が2日連続 | 休息日を挟むよううながす（注意） |
| `没頭` が3日以上連続 | 今日は休息日にするよう求める（強い警告） |
| 今日の寝起きが「悪い」、または `苦しい夢` がある | 「減速日」として、大きな作業や決断を避けるよううながす |

### カレンダー（`/calendar`）

月ごとのカレンダーに、各日の MP を4色で塗り分けて表示します。`クラッシュ` のある日には⚡が付きます。
既定は直近4か月分で、`/calendar?months=12` のように最大24か月まで表示できます。

### ふりかえり（`/insights`）

記録がたまってから傾向を見るためのページです。

| セクション | 内容 |
| --- | --- |
| 週ごとの推移 | 月曜始まりの週ごとに、平均MP・前週との差・各タグ（クラッシュ/没頭/寝起き悪い/苦しい夢/散歩）の日数 |
| 寝起き → その日のMP | 寝起きの良し悪し別に、その日の MP の平均 |
| 寝起き → 翌日のMP | 寝起きの良し悪し別に、翌日の MP の平均（翌日にも記録がある日だけ） |
| 活動タグ別のMP | タグごとに、そのタグを付けた日の MP の平均 |
| 体重の推移 | 体重の記録が2日以上あれば折れ線グラフを表示 |

既定は直近8週分で、`/insights?weeks=26` のように最大52週まで表示できます。

少ないデータで傾向を断定しないよう、次のルールで集計します。

- 件数が5件未満のグループは「参考値」としてバーを薄く表示し、件数を警告色で示す
- 週の平均MPは、記録が3日以上ある週だけ表示する
- 前週との差は、**隣り合う2週の両方**に3日以上の記録があるときだけ表示する

### 活動ごとの消費MP

日次の記録とは別に、「何にどれだけ MP を使ったか」を活動1件ごとに記録できます。
現在は Web 画面からの入力・表示には対応しておらず、Python から `db.py` の関数を呼んで使います。

| 項目 | 内容 |
| --- | --- |
| `mp_cost` | 実際に消費した MP（1〜5 の整数） |
| `mp_estimated` | 事前に見積もった MP（1 / 3 / 5 のいずれか。任意） |
| `minutes` / `tag` / `source` / `note` | 所要時間・分類タグ・記録経路・メモ（任意） |

```python
import db

# 活動を記録する（同じ日・同じ活動名なら上書き）
db.add_activity("2026-08-14", "資料作成", 3, mp_estimated=3, minutes=90, tag="仕事")

db.daily_mp_spent(7)      # 直近7日の、日ごとの消費MP合計
db.estimate_accuracy()    # 見積もり（1/3/5）ごとの、実測の平均とズレ
```

`estimate_accuracy()` は直近90日のうち見積もりが入っている記録を対象に、見積もりごとの実測の平均・ズレと、
見積もりが的中した割合を返します。件数が5件未満のうちは `enough: False` となり、参考値として扱います。

**タグからの補完** — 活動を個別に記録しなかった日でも、日次記録の活動タグは残っています。
`config.py` の `TAG_MP_COSTS`（タグ → 消費MP の表）を使って、タグから活動の記録を起こせます。

```python
db.activities_from_tags("2026-07-29")   # 補完候補を返す（書き込まない）
db.fill_from_tags("2026-07-29")         # 補完して書き込む（source='table'）
```

すでに活動が記録されているタグは補完の対象外です。補完した記録には `mp_estimated` を入れないため、
見積もり精度の集計には影響しません。

### リマインド通知（WSL + systemd）

`install.sh` でセットアップすると、次の仕組みが有効になります。

| 仕組み | 内容 |
| --- | --- |
| サーバの常駐 | systemd のユーザーサービスとして起動し、WSL の起動と同時に立ち上がる |
| 朝夜の通知 | **8:30 と 21:00** に、その日が未記録なら Windows のトースト通知を表示。クリックで入力画面が開く |
| `mplog` コマンド | ブラウザで入力画面を開く |
| シェル起動時の表示 | ターミナルを開いたとき、その日が未記録ならリマインドを表示 |

記録済みの日は、通知もターミナルへの表示も出ません。
通知は WSL から PowerShell 経由で Windows の機能を直接呼んでいるため、Windows 側に追加のインストールは不要です。

## 動作環境

- Python 3.10 以上
- 主な依存パッケージ: FastAPI / Uvicorn / Jinja2（[requirements.txt](requirements.txt)）
- リマインド通知を使う場合: WSL2 + systemd が有効な Linux ディストリビューション

## インストールと起動

### 1. セットアップ

```bash
git clone https://github.com/KannoKens/mp-log.git
cd mp-log

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. 設定（任意）

設定ファイルが無くても既定値で動きます。活動タグを自分用にしたい場合はコピーして編集します。

```bash
cp config.example.py config.py
```

過去の記録をまとめて入れたい場合は、シード用スクリプトをコピーして自分のデータに書き換え、実行します
（すでに記録がある日はスキップされます）。

```bash
cp seed.example.py seed.py
python3 seed.py
```

### 3. 起動

```bash
uvicorn main:app --reload
```

ブラウザで http://127.0.0.1:8000 を開くと入力画面が表示されます。
データベース（`mplog.db`）は初回起動時にリポジトリ直下へ自動で作られます。

### 常駐とリマインドを使う場合（WSL）

毎回 `uvicorn` を起動する代わりに、常駐とリマインド通知をセットアップできます。何度実行しても安全です。

```bash
./install.sh               # セットアップ
./install.sh --uninstall   # 解除
```

セットアップ後に使えるコマンド:

```bash
mplog                                  # 入力画面を開く
systemctl --user status mplog          # サーバの状態を確認
systemctl --user list-timers 'mplog*'  # 次の通知時刻を確認
python3 remind.py --test               # 通知の動作確認
```

通知の時刻を変えるには、`systemd/mplog-remind.timer` の `OnCalendar` を編集してから次を実行します。

```bash
systemctl --user daemon-reload && systemctl --user restart mplog-remind.timer
```

## 設定

`config.py`（[config.example.py](config.example.py) をコピーして作成）で次の項目を設定できます。

| 設定 | 内容 | 既定値 |
| --- | --- | --- |
| `ACTIVITY_TAGS` | 入力画面に「登録済み」として並べる活動タグ | 仕事 / 勉強 / 運動 / 家事 / 趣味 / 外出 |
| `TAG_MP_COSTS` | タグ → 消費MP（1〜5）の表。タグからの補完に使う | なし |

`TAG_MP_COSTS` には、消費量がおおむね一定の活動だけを載せてください。
日によって消費が大きく変わる活動に固定値を置くと、集計が実態とずれます。

## データとプライバシー

健康に関わる個人の記録を扱うため、データはすべてローカルに保存し、外部へは送信しません。
次のファイルは `.gitignore` に入っており、リポジトリには含まれません。

| ファイル | 内容 | リポジトリにあるサンプル |
| --- | --- | --- |
| `mplog.db` | 記録の本体（SQLite） | — |
| `config.py` | 個人の設定 | `config.example.py` |
| `seed.py` | 過去記録の投入用データ | `seed.example.py` |
| `skills/` | AI エージェント（Claude Code）から活動を記録するための個人用スクリプト | — |

全記録は `GET /api/logs` で JSON として取り出せます。

## 開発

### テスト

```bash
pip install -r requirements-dev.txt
pytest
```

テストは一時ファイルの DB を使うため、手元の `mplog.db` には影響しません。

### CI

GitHub Actions（[.github/workflows/ci.yml](.github/workflows/ci.yml)）で、push・プルリクエスト時と週1回、次を実行しています。

- `pytest`
- Uvicorn でサーバを実際に起動し、全ページが応答するかの確認
- `remind.py` が標準ライブラリだけで動くかの確認（systemd のタイマーはシステムの `python3` で実行するため）

### ディレクトリ構成

```
.
├── main.py              # Web アプリ本体（FastAPI のルーティング）
├── db.py                # データベース操作と集計
├── remind.py            # 未記録の日のリマインド通知（標準ライブラリのみ）
├── templates/           # 画面のテンプレート（入力・カレンダー・ふりかえり）
├── config.example.py    # 設定のサンプル
├── seed.example.py      # 過去記録投入のサンプル
├── install.sh           # 常駐・リマインドのセットアップ
├── systemd/             # systemd のサービス・タイマー定義
├── shell/mplog.sh       # mplog コマンドとシェル起動時のリマインド
└── tests/               # pytest のテスト
```
