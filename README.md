# MPログ

その日に使える気力を **MP（残量）** として日次で記録し、活動ごとの**消費量**と突き合わせて、
無理をしそうな日を早めに検知するセルフトラッキング Web アプリ。

調子には波があるのに、手元に残るのは「今日はしんどかった」といった**物語的な記録だけ**で、
日次の定量データが無かった。それだと「何が自分を削っているのか」が推測にしかならない。
そこで、**続く程度に入力を軽くして貯め、たまってから傾向を見る**形にした。

## 見どころ

このリポジトリで読んでほしいのは、機能の数ではなく次の4つの判断です。

| | 内容 | 場所 |
| --- | --- | --- |
| **運用データで UI を畳んだ** | 専用チェックボックスは15日で1回しか使われず、入力口が2つに割れていたのでタグへ一本化。体重・没頭分数の欄も2週間0件で撤去した | [入力はタグに一本化している](#入力はタグに一本化している) |
| **見積もりを実測で較正する** | `/today` が付ける MP1/3/5 は見積もりでしかない。実測を別に持ち、`estimate_accuracy()` で系統的なズレを返す | [活動ごとの消費MP](#活動ごとの消費mpactivities) |
| **少ないデータで断定させない** | 件数の少ないグループは薄く出す、週平均は記録3日以上の週だけ、前週差は隣り合う週の両方が3日以上あるときだけ | [ふりかえり](#ふりかえりinsights) |
| **記録が続く導線を作った** | 常駐サーバ＋**未記録の日だけ**朝夜に通知。WSL から WinRT を直接叩くので Windows 側の追加インストール不要 | [日々使う導線](#日々使う導線wsl--systemd-前提) |

## 動かし方

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install fastapi "uvicorn[standard]" jinja2 python-multipart

# 個人用の設定・データ（任意。無くても汎用のデフォルトで動く）
cp config.example.py config.py   # 活動タグを自分用に編集
cp seed.example.py seed.py        # 過去記録を入れるなら自分のデータに書き換える
python3 seed.py                   # 任意。サンプル/自分の過去記録を投入（既存の日はスキップ）

uvicorn main:app --reload
```

ブラウザで http://127.0.0.1:8000 を開く。

## 入力はタグに一本化している

没頭・散歩・苦しい夢・クラッシュは、以前は専用チェックボックスだった。
運用してみると15日間で1回しか使われず、同じ日の「散歩」が自由記述タグの側に
書かれていた（入力口が2つに割れていた）ため、**タグ側へ一本化した**。

- タグに `散歩` と入れる／押すと `walk` 列が立つ。警告とカレンダーの⚡は従来どおり動く
- 言い換えは吸収する（`悪夢`→`苦しい夢`、`没頭タスク`→`没頭`、`さんぽ`→`散歩` など。
  `db.TAG_ALIASES`）
- 対応表は `db.FLAG_TAGS`。タグ名を増やしたいときはここに足す
- 旧チェックボックスで保存した日を開くと、立っているフラグがタグとして
  復元されるので、編集しても記録は落ちない

タグのボタンは3段構成。**「よく使う」は履歴から自動で作られる**ので、
一度自由記述したタグは次回からワンタップで押せる（`config.py` の編集は不要）。

| 段 | 中身 |
|---|---|
| よく使う | 直近90日で2回以上使ったタグ（`db.frequent_tags()`） |
| 登録済み | `config.py` の `ACTIVITY_TAGS` のうち上段に出ていないもの |
| 体調・状態 | `db.FLAG_TAGS`（没頭・散歩・苦しい夢・クラッシュ） |

体重と没頭分数の入力欄はフォームから外した（2週間まったく使われなかったため）。
DBの列と `/insights` の体重セクションは残してあるので、`templates/index.html` に
入力欄を戻せばそのまま使える。フォームから外れている間も、既存の値は
保存のたびに引き継がれて消えない。

## 活動ごとの消費MP（`activities`）

`daily_logs` は1日1行で、持っているのは**その日の結果**（`mp_level`）だけ。
`caution` の日があっても、**何で削られたか**は後から辿れなかった。
そこで活動を1件1行で持つ `activities` を足した。

| 列 | 意味 |
| --- | --- |
| `mp_cost` | 実測の消費MP（**1〜5 の整数**） |
| `mp_estimated` | 提案時に**見積もった**値（**1 / 3 / 5 のみ**）。無ければ NULL |
| `minutes` `tag` `source` | 任意。`tag` は `daily_logs.activity_tags` の語彙に寄せる |

**見積もりの語彙（1/3/5）は増やさない**（増やすと過去の見積もりと比較できなくなる）が、
**実測は 1〜5 を使う**。実測を3段階に丸めると「MP3と見積もった作業は実際はやや軽い」
というズレが原理的に見えなくなり、較正という目的そのものが損なわれるため。

狙いは活動量の可視化だけではない。提案時に出す MP1/3/5 は見積もりでしかなく
答え合わせの材料が無かった。`mp_estimated` と `mp_cost` を並べることで、
`db.estimate_accuracy()` が「MP3 と見積もった作業は実際 MP4 だった」という
系統的なズレを返せる（件数が `MIN_SAMPLES` 未満の間は `enough: False`）。

```python
import db
db.add_activity("2026-08-14", "資料作成", 3, mp_estimated=3, minutes=90, tag="仕事")
db.daily_mp_spent(7)     # 日ごとの消費MP合計（未記録の日は行ごと出ない）
db.estimate_accuracy()   # 見積もりと実測のズレ
```

同じ日・同じ活動名の `add_activity` は**上書き**。1日に2回記録しても行が増えない。

### 別の環境でやった作業を落とさない（タグ引き）

別のPCなど、記録の導線を通らない環境での作業がある。
ここが 0 件のまま残ると、**「使わなかった日」と「記録し忘れた日」が区別できず**、
翌日に重い作業を積んでしまう。

ただし**やった事実は既にDBにある** — 入力フォームからタグが入力されているため。
欠けているのは消費量だけなので、`config.TAG_MP_COSTS` の表から引く。

```python
db.activities_from_tags("2026-07-29")  # 未記録のタグを提案（書き込まない）
db.fill_from_tags("2026-07-29")        # source='table' で書き込む
```

- 既に活動行があるタグは**対象外**。実測を書いた後に呼べば二重にならない
- `mp_estimated` は入れない → `estimate_accuracy()` を固定値で汚さない
- **表の値は実測ではなく「0 の代わりに置く床」**。同じタグでも
  調子の良い日と悪い日があり、一律の値は粗い。数週間貯めてから
  `daily_mp_spent()` と `mp_level` を突き合わせて表そのものを見直す
- ⚠ **消費量が「読めない」活動は表に載せない**（没頭しやすいプログラミング等）。
  固定値を置くと、実態とズレたまま判断材料になる

**入力の手数を増やさない。** 記録が1手でも増えると続かないので、
下書きは自動で作り、人は数字を直すだけにしている。

## 自動記録との連携（`skills/`・このリポジトリには含めない）

`activities` への書き込みは、手入力ではなく **AI コーディングエージェント
（Claude Code）のスキル**から行っている。2つで対になっている。

| スキル | 役割 |
| --- | --- |
| `today` | 直近のMPと締切から、その日の作業候補を出す（**読むだけ**）。このとき MP1/3/5 を**見積もる** |
| `session-close` | 作業終了時に、やった活動と消費MPを `activities` に**実測**として書き、関連プロジェクトのメモを更新する |

見積もりと実測がこの往復で揃うので、`db.estimate_accuracy()` が答え合わせを返せる。
スキルの実体は `~/.claude` ではなくこのリポジトリ側に置き、`~/.claude/skills/<name>` から
symlink する（`~/.claude` は git 管理外で、壊したときに戻せないため）。`./install.sh` が張る。

> ⚠ **スキル本体のファイルはこのリポジトリには含めていない**（`.gitignore` 済み）。
> 中身が個人のメモのファイルパスに依存していて、汎用化できていないため。
> 設計は上記のとおりで、参照される API は `db.add_activity()` / `db.estimate_accuracy()`。

## ふりかえり（`/insights`）

記録がたまってから見るページ。入力画面・カレンダーから飛べる。

| セクション | 内容 |
|---|---|
| 週ごとの推移 | 月曜始まりの週別に、平均MP・前週差・クラッシュ/没頭/寝起き悪い/苦しい夢/散歩の日数 |
| 寝起き → その日のMP | 「寝起きの悪い朝は崩れやすい」仮説の検証 |
| 寝起き → 翌日のMP | 前日の寝起きが翌日まで尾を引くか（翌日にも記録がある日だけ集計） |
| 活動タグ別のMP | その活動をした日のMP平均。何が削っているかの当たりをつける |
| 体重の推移 | 体重を入れた日が2日以上あれば折れ線を表示 |

平均MPは4択を代表値（絶好調17／安全圏10／やや注意7／危険3）に直して計算する。

**数値の読み方の注意** — 少ないデータで傾向を断定しないための作りにしてある。

- 件数が `MIN_SAMPLES`（既定5）未満のグループはバーを薄くし、`n=` を警告色で出す
- 週の平均は記録3日（`MIN_WEEK_DAYS`）以上ある週だけを「その週の代表値」として扱う
- 前週差は**隣り合う週の両方**が3日以上記録されているときだけ表示する
  （記録の空白を挟んだ週どうしを比べて、急変したように見せないため）

## 日々使う導線（WSL + systemd 前提）

毎回 `uvicorn` を起動するのが面倒で記録が続かないので、常駐＋リマインドを入れる。

```bash
./install.sh            # セットアップ（何度実行しても安全）
./install.sh --uninstall # 解除
```

`install.sh` がやること:

| | 内容 |
|---|---|
| 常駐 | `mplog.service`（systemd user）で uvicorn を自動起動。WSL 起動時から立ち上がる |
| リマインド | `mplog-remind.timer` が **朝 8:30 / 夜 21:00** に起動し、**その日が未記録のときだけ** Windows のトースト通知を出す（クリックで入力画面が開く） |
| シェル | `.bashrc` に1行追記し、`mplog` コマンド（ブラウザで入力画面を開く）と、シェル起動時の未記録リマインドを有効化 |

記録済みの日は通知もターミナル表示も出ない。時刻を変えるときは
`systemd/mplog-remind.timer` の `OnCalendar` を編集して
`systemctl --user daemon-reload && systemctl --user restart mplog-remind.timer`。

```bash
mplog                                  # 入力画面を開く
systemctl --user status mplog          # サーバの状態
systemctl --user list-timers 'mplog*'  # 次のリマインド時刻
python3 remind.py --test               # 通知の動作確認
```

トースト通知は WSL から `powershell.exe` の WinRT API を直接叩いて出しているので、
Windows 側に追加インストールは不要（BurntToast 等は不使用）。
